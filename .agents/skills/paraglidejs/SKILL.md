# Paraglide JS

Compiler-based, tree-shakeable i18n. Messages live in `messages/{locale}.json`, compile to `src/paraglide/`, and are called as type-safe functions.

Source of truth: https://paraglidejs.com/basics, https://paraglidejs.com/message-keys, https://paraglidejs.com/compiling-messages, https://paraglidejs.com/tanstack-router, https://paraglidejs.com/react-router, https://paraglidejs.com/strategy, https://paraglidejs.com/monorepo. Prefer docs over memory.

## Message keys (required pattern)

Follow https://paraglidejs.com/message-keys.

For all NEW messages, use flat, random human-readable keys. Treat the key like a database ID, not documentation.

```json
// messages/en.json - DO
{
  "calm_green_otter": "Log in",
  "bright_coral_fox": "User Profile"
}
```

```ts
import { m } from "./paraglide/messages.js";
m.calm_green_otter();
```

Do NOT do this for new messages:

```json
// DON'T - semantic, nested, or copy-derived keys
{
  "login_button_label": "Log in",
  "nav.home": "Home",
  "user": { "profile": { "title": "User Profile" } }
}
```

Why:
- Semantic keys (`login_button_label`, `user.profile.title`) invite renames when copy or UI placement changes. Renames break call sites, lose translation history/comments/screenshots attached to the key, and look like delete+create to translation tools.
- Random keys are stable, need no naming convention (`snake vs kebab`, `login vs auth`), and can be generated by anyone (Sherlock VS Code extension does this on extract).
- Flat keys compile to direct function calls (`m.key()`) with go-to-definition, auto-import, and tree-shaking. Nested keys only work via bracket notation (`m["nav.home"]()`) and add complexity for translators and tooling.

Rules:
1. New messages: generate flat random `adjective_color_animal` style key.
2. Never rename an existing key just to make it random. Stability beats style. Keep `example_message` as-is until a controlled migration.
3. Never reuse one key in two unrelated UI spots even if text matches today (`"OK"` in two places = two keys). They evolve independently.
4. Finding copy: search source-locale JSON for text -> get key -> search codebase for key. Sherlock shows content inline on hover to remove this friction.
5. Dynamic lookup: map explicitly to preserve tree-shaking, don't index `m` by string:

```ts
import { m } from "./paraglide/messages.js";
const navMessages = { home: m.calm_green_otter, about: m.bright_coral_fox } as const;
navMessages[item.key]();
```

Migration (only when intentional, migrate all locales + call sites + tools together):
- Nested to flat, keep ID: `{"nav":{"home":"Home"}}` -> `{"nav.home":"Home"}` used as `m["nav.home"]()`.
- To new random IDs: `{"nav.home":"Home"}` -> `{"calm_green_otter":"Home"}` used as `m.calm_green_otter()`.

## Using messages

```ts
import { m } from "./paraglide/messages.js";
m.hello_world();
m.greeting({ name: "Samuel" }); // messages/en.json: { "...": "Hello {name}!" }
m.greeting({ name: "Samuel" }, { locale: "de" }); // force locale, useful for SSR
```

Type-safe strings: message fns return `LocalizedString`. Type props as `LocalizedString`, not `string`.

## Locale runtime

```ts
import { getLocale, getTextDirection, setLocale, localizeHref } from "./paraglide/runtime.js";
getLocale(); // "en"
getTextDirection(); // "ltr" | "rtl"
setLocale("de"); // full document navigation / reload by default
localizeHref("/blog"); // "/en/blog" or "/de/blog"
```

- `setLocale()` navigates/reloads to re-render app + `<html lang dir>` together. Use it for normal pickers.
- `setLocale(locale, {reload:false})` is client-only escape hatch for widgets/extension pages that must keep in-memory state. Never use on SSR/SSG docs or with `url` strategy.
- In Astro layout: `<html lang={getLocale()} dir={getTextDirection()}>`.

## Adding messages and locales

`messages/en.json`:
```json
{
  "$schema": "https://inlang.com/schema/inlang-message-format",
  "calm_green_otter": "Hello {username}"
}
```

Add same key to every `messages/{locale}.json`. Add locale in `project.inlang/settings.json`:
```json
{ "baseLocale": "en", "locales": ["en", "de"] }
```

Then recompile (Vite plugin does it automatically in dev/build, CLI for CI):
```bash
paraglide-js compile --project ./project.inlang --outdir ./src/paraglide --emit-ts-declarations
```

## React

Messages are plain functions, not hooks. Call `m.*()` directly in render. `setLocale()` does a full document navigation/reload by default, so the re-render comes for free. Do not wrap messages in state or try to make locale switching reactive.

```tsx
import { m } from "@/paraglide/messages.js";
import { getLocale, setLocale, localizeHref } from "@/paraglide/runtime.js";

export function Greeting({ name }: { name: string }) {
  return <h1>{m.calm_green_otter({ username: name })}</h1>;
}

export function LocaleSwitcher() {
  const locale = getLocale();
  return (
    <div>
      <span>Current: {locale}</span>
      <button onClick={() => setLocale("de")}>Deutsch</button>
      <a href={localizeHref("/blog")}>{m.bright_coral_fox()}</a>
    </div>
  );
}
```

Rules:
- Import via `@/paraglide/messages.js` / `@/paraglide/runtime.js` (alias in `apps/web/tsconfig.json`), or relative `../../paraglide/...` from `src/dashboard/`.
- Links: use `localizeHref("/path")`, never hardcode `/en/...`.
- Forcing locale per call (`m.key(..., { locale: "de" })`) is for SSR/emails, not normal rendering.
- Never use `setLocale(locale, { reload: false })` for a normal picker. It skips navigation and leaves `<html lang>`, URL, and SSR state stale. Only for fully client-owned surfaces with no `url` strategy.
- Type localized props as `LocalizedString`, not `string`.

TanStack Router (this repo's dashboard is embedded in Astro, strategy `["cookie","baseLocale"]` — no URL prefixing, so no rewrite needed today). If `url` strategy is added later:
```ts
import { deLocalizeUrl, localizeUrl, shouldRedirect } from "@/paraglide/runtime.js";
const router = createRouter({
  routeTree,
  rewrite: { input: ({ url }) => deLocalizeUrl(url), output: ({ url }) => localizeUrl(url) },
});
// offline/CSR redirect guard in root route beforeLoad:
// const d = await shouldRedirect({ url: window.location.href });
// if (d.redirectUrl) throw redirect({ href: d.redirectUrl.href });
```

React Router v7 framework mode (for reference, not this repo): prefix routes with `:locale?`, enable middleware (`paraglideMiddleware` in `root.tsx`), and keep `urlPatterns` in sync so `localizeHref` matches route definitions.

## Monorepo / shared packages

Follow https://paraglidejs.com/monorepo Pattern 1 (each app compiles, recommended). Keep the locale strategy in the app, never in a shared UI package.

- Simplest (preferred): shared components accept already-translated strings. The app calls `m.*()` and passes the result as a prop typed `LocalizedString`.
```tsx
// packages/ui: no paraglide import
export function SaveButton(props: { label: LocalizedString }) {
  return <button>{props.label}</button>;
}
// app: import { m } from "@/paraglide/messages.js";
<SaveButton label={m.calm_green_otter()} />
```
- Only if the UI package owns reusable messages: compile that package with fallback `--strategy baseLocale`, expose `initUiI18n({ getLocale, setLocale })` via `overwriteGetLocale`/`overwriteSetLocale`, and call it once from the app entrypoint before rendering. The package must not read URL/cookie/storage itself; request safety comes from the app runtime.
- Do not create a shared i18n package (Pattern 2) unless every consumer uses the identical strategy. It forces one strategy on all apps.

## This repo (Astro)

One shared catalog at the repo root (`project.inlang/` + `messages/{en,de}.json`), compiled per package (Pattern 1). Details: `docs/i18n/README.md`.

- Dashboard (`apps/web`): `apps/web/astro.config.mjs` uses `paraglideVitePlugin({project: paraglideProjectDir, outdir: "./src/paraglide", strategy:["cookie","baseLocale"]})`, where `paraglideProjectDir` is the absolute repo-root `project.inlang` resolved via `fileURLToPath(new URL("../../project.inlang", import.meta.url))`. Middleware: `apps/web/src/middleware.ts` uses `paraglideMiddleware`. Generated output `apps/web/src/paraglide/` is a git-ignored build artifact — never hand-edit. Import via `@/paraglide/*`. Check types runs `pnpm build:paraglide && astro check`. Machine translate: `pnpm --filter web machine-translate`.
- Public board (`apps/public-feature-board`): compiles from the shared root project with `--project ../../project.inlang --strategy baseLocale --emit-ts-declarations` (`pnpm --filter @feeblo/public-feature-board build:paraglide`; its `dev` watches). Import messages relatively (`../paraglide/messages.js`). The package must never read cookies/URL itself: the host injects its runtime via `initPublicBoardI18n({ getLocale, setLocale })` (`src/i18n.ts`) from `apps/web/src/public-board/public-board-island.tsx`, which wraps `<PublicBoardApp client:only="react" />` once before render. Locale changes flow through the host's cookie strategy.
- Shared post UI (`packages/post-ui`): same pattern — compiles the shared root project with `--strategy baseLocale --emit-ts-declarations`, relative imports, `initPostUiI18n` exported from `@feeblo/post-ui/i18n`. Both hosts initialize it: the dashboard in `apps/web/src/dashboard/main.tsx` and the board island. `docs/i18n/post-ui.md` has the details (including Zod `{ error: () => m.x() }` and per-call default params).
- Turbo: `build:paraglide` is a task with `inputs: ["$TURBO_DEFAULT$", "$TURBO_ROOT$/project.inlang/**", "$TURBO_ROOT$/messages/**"]` and `outputs: ["src/paraglide/**"]`; `check-types` depends on `build:paraglide` + `^build:paraglide` so generated types exist before `tsc`/`astro check` and `apps/web` waits for the board's compile. `pnpm dev:web` runs both dev watchers.
- New keys: generate with `@inlang/sdk`'s `humanId()` (slice to 3 words to match the existing catalog), never a hand-rolled word list. Brand names stay hardcoded.
